# LeadStream Mobile

Expo SDK 57 + expo-router (TypeScript, plain StyleSheet, dark theme). The owner's phone UI
for the LeadStream Reddit lead monitor: browse leads, get push alerts for hot ones, and grab
an AI-drafted reply to paste on Reddit.

Backend = the Next.js app at the repo root (`/api/leads`, `/api/reply`, `/api/devices`,
`/api/scan`, all gated by the `x-app-secret` header).

## Run it (Expo Go)

```bash
cd mobile
npm install
npx expo start
```

Scan the QR code with Expo Go (iOS) or the Expo Go app (Android).

Work from a plain local folder (`C:\dev\leadstream\mobile`), not Dropbox/OneDrive — Metro
and `npm install` misbehave inside synced folders.

## First-launch setup

The app opens on **Settings** until it is configured:

1. **API base URL** — your deployed backend, e.g. `https://leadstream-murex.vercel.app`
   (the default is a placeholder; change it to the real Vercel domain).
2. **App Secret** — the `APP_SECRET` env var set on Vercel.
3. Tap **Save & test**. The app calls `GET /api/leads` to verify both values, stores them in
   the device keychain (expo-secure-store), asks for notification permission, and registers
   the phone's Expo push token via `POST /api/devices`.

Settings is always reachable from the gear icon on the leads list. It also shows the push
permission state, the (truncated) push token, a **Register this phone for alerts** button,
and **Run scan now** (`POST /api/scan`, which can take up to 5 minutes).

## Screens

- **Leads** — cards with score badge, intent chip, location (or subreddit), relative time,
  title, and one-line reasoning. Filters: All / Hot (≥70) / Service / Unhandled.
  Pull-to-refresh, plus auto-refresh every 60 s while the screen is focused.
- **Lead detail** — full post, meta, score reasoning, **Open on Reddit**, **Draft AI reply**,
  **Copy reply**, **Open Reddit & copy**, **Mark replied** / **Skip**.
- Push taps open the matching lead (looked up by `reddit_id`; the list is refetched if
  needed; falls back to opening the Reddit URL in the browser).

### Handled status is local (for now)

The backend has no status-update endpoint yet, so "replied" / "skipped" live in
AsyncStorage on the phone (`src/lib/handled.ts`). The UI only talks to the `StatusStore`
interface — when a server route exists, add a server-backed implementation and swap
`statusStore` in that file.

## Build later (EAS)

The app has its own slug `leadstream` and bundle id `com.tradestream.leadstream`
(iOS + Android). No EAS project has been created yet:

```bash
cd mobile
npx eas init            # creates the EAS project and writes extra.eas.projectId into app.json
npx eas build --profile preview --platform android   # internal APK
npx eas build --profile production --platform ios
```

`src/lib/push.ts` reads `Constants.expoConfig.extra.eas.projectId` when present, so push
tokens start working for real builds as soon as `eas init` has run.

Remote push also needs push credentials on the EAS project:
- **iOS**: an APNs key (`eas credentials` → iOS → Push Notifications; one .p8 key works
  for the whole Apple team — check whether another portfolio app already has one).
- **Android**: FCM v1 service-account JSON (`eas credentials` → Android → FCM).

## Placeholder assets

`assets/*.png` (icon, adaptive icon, splash icon, favicon) are generated by
`node scripts/make-assets.js` — a solid `#0d1117` square with an orange "LS" in a 5×7
pixel font, written with a zero-dependency PNG encoder. Replace them with real artwork
before a store release.

## Known limitations

- **Android Expo Go cannot receive remote push** (Expo SDK 53+). Use a development build
  or a production build. iOS Expo Go still receives remote push.
- The leads list is the server's latest 200 non-noise leads; older leads will show
  "Lead not found" if opened from an old notification.
- Handled status is per-phone until a server endpoint exists (see above).
- Scanning from the phone holds an HTTP request open for up to 5 minutes; if the phone
  sleeps mid-scan the request may drop, but the server-side scan finishes regardless.
